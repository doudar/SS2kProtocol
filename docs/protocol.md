## Framing and behavior

- Requests are [operation, command ID, payload]. Responses/notifications are [status, command ID, payload]. All multi-byte integers are little-endian; signed integers use two's complement.

- Read means writing a read request to the characteristic; the GATT characteristic exposes WRITE, INDICATE, NOTIFY, not GATT READ.

- Subscribe to indications for command replies and notifications for updates. Serialize requests. ATT write completion is not protocol completion. Shifter writes finish via a later notification. Most successful writes echo the request payload; read back when setters can normalize or ignore values.

- Canonical booleans are one byte, 0 or 1. Legacy firmware accepts nonzero true and often ignores trailing write bytes (the old app sends two boolean bytes). This library emits canonical packets and accepts legacy boolean write echoes only when requested explicitly.

- Strings are unprefixed bytes with no on-wire terminator. New clients use UTF-8 and exclude embedded NUL because firmware string setters use C strings. Firmware does not validate UTF-8; C codecs expose byte views.

- Errors begin FF <ID>; some legacy paths echo additional request bytes. Do not decode an error payload as a setting. Packets shorter than two bytes can be silently ignored by firmware.

- Normal ATT value capacity is MTU-3. Snapshot chunks and scan events have explicit fragmentation; other large values (including 63-byte power rows, needing MTU >=66) require sufficient MTU or a transport-supported long write. Never invent generic fragmentation.

- DirCon carries identical protocol bytes: first command response in characteristic-write response, updates as notifications. Snapshot remaining chunks follow as notifications; current DirCon snapshot payload is 200 bytes per chunk.

- Snapshot header: status@0, ID@1, version u8@2, chunk u16@3, count u16@5, JSON bytes@7. Count >0, chunk<count. Snapshot transfer blocks other BLE commands and expires after 5000 ms without progress.

- Scan header: status@0, ID@1, version u8@2, event u8@3, scan ID u16@4, sequence u16@6, fragment u8@8, count u8@9, body@10. Count >0, fragment<count. Begin/end carry no body. Device body is [UUID length u8, UUID UTF-8, name UTF-8].

- This manifest version identifies the library, not a newly negotiated on-wire version. Existing IDs, UUIDs and layouts are preserved. Unknown IDs fail locally; older devices can return FF for newer commands.

- App metadata contains presentation defaults/ranges from the companion app, not firmware-enforced limits or board-dependent factory defaults. Wire validity and application policy are separate.

- With capability bit 1, only capabilities and secure v1 discovery/handshake frames are public. All settings, updates, logs and firmware operations travel inside authenticated secure records. See docs/secure.md for the handshake, replay rules and transport framing.

- Inside a secure record, status 0x81 marks an unsolicited setting change, scan event or log. It never acknowledges a write or read. Request-bound snapshot chunks carry success 0x80. Shifter writes receive an explicit command acknowledgement.

## Payload formats

`empty`: no bytes. `bool`: one byte; zero false, nonzero true on receive. `u16`/`i16`/`i32`: exactly 2/2/4 little-endian bytes. `string`: all remaining bytes. `row_index`: one row byte. `power_table`: row byte + 30 signed LE16 values. `gear_index`: empty metadata request or one index byte. `gear_write`: count byte + count LE16 pairs. `gear_reply`: count byte, optionally index byte + LE16 pair. `snapshot` and `scan`: full headers described above (the status/ID are included in header lengths).

### BLE_powerTableData (`0x27`)

Power Table Data. Status: active.

Row is followed by 30 signed LE16 stored positions (motor steps divided by 10). -32768 means unknown. First uploaded row queues startup homing, sets hMin to zero, and schedules delayed table persistence. Legacy invalid row reads fall back to row 6; invalid row writes may report success without applying. New clients must reject invalid row indexes.

### BLE_allSettings (`0x31`)

allSettings. Status: active.

Read-only user-config JSON snapshot, not every runtime measurement. Reassemble UTF-8 bytes before parsing JSON. Unknown JSON keys must be ignored. The password field is empty when the device supports password-write-only capability. Retry from the start after disconnect, missing chunks or inconsistent framing.

### BLE_scanResults (`0x32`)

scanResults. Status: active.

Notification-only scan stream. Trigger with 02 24. Begin sequence is zero; device sequences start at zero; end sequence is number of devices. Reassemble fragments per scan ID and sequence, then parse [UUID byte length, UUID UTF-8, name UTF-8]. End does not guarantee that all notifications arrived.

### BLE_gearTeeth (`0x34`)

Simulated Groupset. Status: active.

Pair = front*100+rear. Zero pairs selects Unlimited; otherwise 2-26 unique pairs, front/rear 1-99, rounded ratio 500-6000 thousandths. Firmware sorts by ratio then packed pair. Write selects preset 0. Named preset 1 makes tooth reads fail. Metadata/changed response is count only; indexed reads add index and pair. Save using 02 18. Maximum write is 55 bytes (ATT MTU >=58).

### BLE_gearPreset (`0x35`)

Groupset Preset. Status: active.

0 selects Unlimited (or identifies custom teeth on read); 1 selects Mixed Terrain 1x24. Unknown IDs fail. Read 0x34 as well to distinguish Unlimited from a bounded tooth profile. Save using 02 18.
